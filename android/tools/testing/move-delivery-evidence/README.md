# Resumed move completion and request-owned preparation errors

Screen-owned moves now publish an exact completion receipt instead of retaining the screen's Back callback in the mutation. A rememberSaveable route ID binds the receipt to the original navigation entry; a separate live owner prevents old screen callbacks from consuming it. The production collector runs on Main, uses AndroidX repeatOnLifecycle(RESUMED), rechecks the current lifecycle state and consumes the exact receipt before invoking the latest screen callback. Receipts survive owner replacement for the same saved route, are rejected/dropped for a different route, and cannot be replayed by copying a receipt or completing an accepted review twice. Programmatic callers without a screen owner retain their existing success callback.

Move and restore preparation now report errors through the same atomic request owner as review publication. Superseded or disposed requests cannot replace the current preparation error. Beginning a valid current review clears the prior shared error once at explicit dispatch; delayed preparation does not later clear that shared channel. Other repository operations and accepted-move failures still use the existing shared error channel. Native preparation expectations now read moveReviewError; no native tests ran.

Twelve new JVM tests use the actual AndroidX LifecycleRegistry and production delivery collector, with a test Main dispatcher. They cover waiting at STARTED, completion while backgrounded, resume without replay, saved-route owner replacement before/after completion, different-route rejection, copied receipts, destroyed lifecycle, cancelled collectors and current/stale preparation errors. Reviews are prepared from generated real Git repositories; these tests signal completion/error state directly and do not execute a filesystem move or SettingsViewModel. The previous move/real-Git and state regressions continue to pass. This proves the library/state behavior, not real Activity lifecycle events, saveable navigation restoration or Android catalog/credential callbacks.
