# App-language casing for display labels

Three display-only caps headings now use the current Compose `LocalConfiguration` locale, with the existing default-locale fallback for an empty list: commit detail labels, the shared rebase/merge state hero kicker and the Vault state eyebrow. This matches the pattern already used by the Settings and Tide section headings. Branch Current and stash Apply/Pop controls now display their resource values directly. The private legacy branch sentence-case helper and stash lowercase/title-case passes were removed, preserving authored case and diacritics.

Only the five named UI source files changed in this phase. Branch/ref names, identifiers, protocol/account-key normalization, repository/model behavior, localization resources and the 468 English source fixtures are unchanged. Existing Root-based technical key normalization and account monogram behavior are outside this translated-label change.

`UiCaseSpotCheck.java` runs in an isolated Java 17 process with English default and explicitly selected Turkish/German/Japanese locales. Five manual expected-value probes pass, including dotted/dotless I and German sharp-s expansion. It also demonstrates the old Root-case mismatch and combining-dot artifact from forced legacy sentence case. **These are JDK/library probes, not execution of the production Compose functions or Android locale resolution.** No new app JVM tests were added for these small display changes. Actual live app-language change, native text rendering, typography/wrapping, screen readers and linguistic acceptance remain pending.

All **47 existing app JVM tests across four suites**, debug APK, Android-test APK, release APK and release lint pass on the fixed snapshot in **4m 7s**. Catalog/native-expectation checks and all **25 tooling tests** pass on those exact files. **638 snapshot inputs**, 14 tooling inputs, 84 archived passing XML files and three APK hashes are pinned. Core source is unchanged: 192 input / 80 result hashes match the preceding **690-test** proof; core tests were not rerun. The JVM suites do not qualify the rendered casing.

The current Vault source retains the app-locale casing fix, confirmed by source inspection; its later scrolling/layout edit and the other changed files are not build-qualified by this snapshot.
