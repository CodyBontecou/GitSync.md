# Author and upstream review ownership

Both settings editors now require the exact state displayed by the Save callback. A callback from another repository or an earlier same-folder review cannot use the newly loaded plan. Every loading/loaded/error state carries a request ID so an otherwise-identical reload is visible to equality-based UI collectors. The screens capture an immutable state value in callbacks. Existing generation checks under the canonical repository lease, config revisions and locked publication remain in place.

Draft fields initialize synchronously from the reviewed state, keyed by route, request ID and plan. A new review therefore does not initially render a prior review's retained draft while waiting for a population effect. Busy/error copies of the same review retain its current fields. Save completion effects also check that their saved state is still current. Activity recreation, rendered stale callbacks and lifecycle navigation remain native-validation requirements; JVM checks do not establish those behaviors.

Eight parameterized JVM scenarios run against each production ViewModel (sixteen cases): stale callback after a repository switch; same-folder reload; distinct StateFlow review after an unchanged reload; queued save followed by switch; queued save followed by reload; current config-only save with duplicate suppression; external config change; invalid draft. They use real temporary Git repositories, core services, config publication and canonical leases. They verify preservation of the other repository and all non-config bytes for successful saves, including history/index/worktree. RepositoryAuthors is mocked; fixture-local author fields avoid account fallback and Android preference access. No transport or real account operation is involved.
