# Accurate conflict version byte counts

ConflictSide now carries nullable indexed Git blob byte size. ConflictIndex obtains that size from the object reader even when binary, invalid UTF-8, oversized or LFS pointer data cannot be shown in the text preview. Non-blob Git entries remain unknown; absent versions remain absent. Conflict exposes side counts without inventing zero for deleted/unknown sides. Descriptor-free readable legacy text uses its UTF-8 representation as a fallback. An LFS pointer's blob size is deliberately not the hydrated asset size.

Conflict rows use those side counts and retain explicit Yours/Theirs role names when deleted or unknown. Merge/rebase version cards receive the correct side's size, including the incoming/local mapping during rebase. Readable cards use UTF-8 size rather than UTF-16 length; known blob sizes avoid re-encoding. Unsupported previews show available byte size without a fabricated line count, or omit unknown statistics, and display the existing whole-version guidance. The merge manual field is disabled for unsupported previews. Git content/resolution operations are unchanged.

Ten new real-Git regressions create actual unmerged index entries and inspect them through LocalConflictRepository: Unicode/emoji/CRLF with ancestor size, present empty blobs, deletion on either side, binary data, invalid UTF-8, oversized blobs, LFS pointers, Gitlinks and legacy readable/unknown model behavior. The UTF-8 example is **8 bytes rather than 5 UTF-16 units**. Each Git fixture's complete file-byte map, including metadata/index, is checked unchanged after inspection. Whole-file/rename/rebase/transport/discard regressions also run in the full suite.
