# Reviewed move confirmation ownership

The production move sheet previously stored only a Boolean confirmation flag and invoked `moveReviewed(onBack)`, which read the current review at invocation. A retained callback could therefore authorize a replacement destination. The screen now captures an immutable collected review and stores the exact review used to open the confirmation sheet. The sheet renders only while that review is current, displays its destination and passes it explicitly to `SettingsViewModel.moveReviewed(review, onBack)`.

The ViewModel rejects stale review objects before dispatch and after waiting for catalog serialization. Its `beforeMove` callback rechecks exact review identity inside `RepositoryMove.execute`'s checkout leases, before journal creation or relocation. The guard additionally checks that the plan source matches the reviewed repository metadata. Cleanup clears only the review it owns. Existing catalog, filesystem-fingerprint and credential checks remain connected. Prepare/restore requests now receive ownership tokens before asynchronous dispatch; clearing or superseding a request prevents its completed plan from being published. New prepare requests and clearing remain disabled after destructive execution is accepted, preserving the existing durable move-completion behavior.

Seven new app JVM regressions execute the actual `RepositoryMove` service against generated Git working copies and real checkout leases. They cover a cleared review, structurally equal replacement, replacement destination, replacement repository, mismatched metadata, a successful same-volume move and a successful simulated cross-volume copy with retained original. Rejected requests preserve every source/other-checkout file byte, publish no destination/staging/recovery owner and create no move journal. Successful requests preserve checkout bytes and the unrelated repository, with exactly one catalog callback. The cross-volume case injects volume classification; it does not use a physical second volume.

These tests exercise the same guard used by the production callback, not `SettingsViewModel`, Compose, Android catalog/credential persistence or native lifecycle events. Request-token publication and UI capture have source/build evidence only. Device qualification, leaving/reentering the route during review preparation, old callbacks around lifecycle changes and completion-navigation ownership remain open. No native test was executed. Existing native callers were updated to supply an explicit review and compile in the instrumentation APK.
