# Reviewed Settings sign-out

Settings now opens an opaque, in-memory sign-out review tied to the displayed session revision. Its login label stays fixed while the dialog is shown. Confirm and dismiss callbacks own the exact review; old callbacks cannot submit or dismiss a replacement dialog. A session revision invalidates the active review, and an old button callback cannot open a review for a newer revision. Reviews are not serialized and expose no token fields.

The auth manager checks review ownership, revision and session before starting. Inside the encrypted-store update callback it compares the freshly read, normalized session against the reviewed session before forming the disconnected record. A current confirmation clears only the reviewed active account token, preserving other accounts, default-account assignment and aliases. Changed persisted state fails before publication. The ViewModel leaves current requests running when confirmation is rejected and clears them after successful sign-out. Programmatic sign-out used to cancel a pending sign-in remains available with its prior behavior.

Fourteen JVM cases execute the actual auth manager, session-lock and ViewModel code with generated account data. They cover account switches (including away-and-back), same-token session refresh, another manager's review, externally replaced persisted account/token, current sign-out and duplicate protection, persistence failure/retry, dismiss/re-review ownership, stale entry, session invalidation and retained current profile loading after rejection. Android encrypted storage and preferences are mocked; the real store update callback executes against a synthetic persisted Session before simulated publication. The API fixture suspends without making network requests. These checks do not establish Android Keystore behavior, disk rollback, cross-process transactions, rendered dialog semantics or native lifecycle behavior.
