# Complete base-resource discovery and source review

The extractor, iOS importer and native expectation generator now share `base_resource_files`, which reads every XML file directly under the base `values` directory. Android strings/plurals no longer disappear from the inventory when a filename starts with `strings_` or uses another name. Non-string resources are parsed without adding style items to localization coverage. Native English expectations now validate **resource key plus exact source**, allowing two differently named resources to share English text while still rejecting changed wording.

Two original regression cases failed: importing prefix/arbitrary/plural filenames counted one string instead of three, and extraction proposed a duplicate key for an existing label. After the fix, integration coverage also checks translated XML, native expectation generation, duplicate English labels and rejection of an actual changed source. A third regression failed when re-extraction encountered reviewed fixture metadata. Extraction now verifies the name/source/argument fields and preserves the original-source/review annotations.
