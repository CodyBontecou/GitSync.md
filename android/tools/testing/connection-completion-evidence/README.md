# Connection save completion ownership

After saving a repository connection, the visible screen now owns the metadata refresh as a suspending call. Leaving or pausing the screen cancels that call and its navigation delivery. A completed refresh checks the exact saved review and route again before returning. Same-folder reloads and switches invalidate the old completion, duplicate completions are suppressed, and failed or cancelled refreshes leave the saved connection available for retry. Settings no longer stores a navigation callback for this operation. The existing serialized catalog read/update/persist sequence is retained.

Nine new app JVM cases use the production ConnectionViewModel with real temporary Git repositories and config publication. They cover unsaved entry, another route, a stale callback before refresh, delayed same-folder reload, delayed repository switch, cancellation swallowed by a refresh dependency plus retry, failed refresh plus retry, duplicate in-flight/finished completion, and a newer saved connection while an older refresh remains pending. The Android encrypted-store boundary and metadata-refresh dependency are mocked. These tests establish request/delivery ownership, not Android persistence or Compose/lifecycle/navigation behavior.
