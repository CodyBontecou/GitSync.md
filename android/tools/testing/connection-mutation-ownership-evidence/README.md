# Connection save/migration review ownership

Four real-ViewModel JVM regressions failed against the old APIs: save and embedded-URL credential migration accepted a callback captured before another-repository selection or same-folder reload. The tests use owned temporary Git repositories; the encrypted credential-store boundary is mocked. Original failure XML/logs are retained. Save and migration now require the exact reviewed `State`. All three connection mutations pass that same state into the shared executor, which rechecks identity/busy/completion before publishing busy state, and retains the existing generation check after the canonical repository lease. Core configuration/metadata and credential-record version checks remain intact. The old unreviewed save and no-argument migration entry points were removed.

A fifth reproduced failure showed otherwise-identical reload states compare equal. State now carries the load request ID, including loading and error publications, so equality-based UI collectors can publish a fresh review. The JVM test proves distinct state with an unchanged connection plan and checks a structural-equality StateFlow mirror. It does **not** execute Compose.

Production UI reads one state value per composition, then captures that immutable reference for actions. This avoids reading a later delegated state inside an old callback. Form initialization is keyed by request ID/config revision; new reviews are wired to clear temporary token/SSH fields. Observed request checks guard stale initialization/confirmation effects, and saved-state effects check current owner before starting metadata refresh. One existing native queued-migration caller was updated to pass its active review. These UI/lifecycle/navigation/secret-clearing changes are source/build-verified **only**; native event delivery and later asynchronous catalog/navigation completion remain unqualified.
