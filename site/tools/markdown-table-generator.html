How Markdown tables work

A table is a header row, a separator row of hyphens, then any number of body rows. Cells are split by pipes. Colons in the separator row set alignment: :--- left, :---: center, ---: right. Per the GFM spec, the header row must match the separator row in number of cells, or no table is recognised. Leading and trailing pipes are optional but recommended. A body row with fewer cells gets empty cells, and extra cells are ignored. The table ends at the first empty line.

| Task | Owner | Done |
| :--- | :---: | ---: |
| Book the room | Sam | 1 |
| Use a \| pipe | Alex | 2 |

To put a pipe in a cell, write \|. GitHub Docs say the same in Organizing information with tables. The GFM spec adds that this also works inside other inline spans: a pipe inside a code span still splits the cell unless it is escaped, so the tool escapes it there too.

When you import, a row with fewer cells than the header is padded with empty cells. A row with more cells than the header gets new columns instead of losing data, which differs from GitHub, where the extra cells are ignored. Importing a Markdown table also reads \| as a pipe, so it is never escaped twice.

Tables in Obsidian

Obsidian’s Help page on Advanced formatting syntax describes tables made from vertical bars and hyphens, with outer bars optional and at least two hyphens in the header separator. You add colons to that row to align a column, or right-click a table in Live Preview to align it. Also in Live Preview, you can right-click a table to add or delete columns and rows, and sort and move them from the same menu.

The page also warns that if you want to use aliases, or resize an image, in a table, you need to add a \ before the vertical bar. So [[Note|Alias]] becomes [[Note\|Alias]] inside a table. Without it the pipe splits the cell, which is how those tables break. Turn on “Escape pipes in wikilinks (Obsidian)” and the tool does this for you. When you import a table, a pipe inside [[…]] is treated as part of the link rather than a cell break.

Obsidian’s Help doesn’t say anything about <br> in table cells, so check a note with line breaks in your own vault before you rely on it. Obsidian also has Bases, which is a separate view for notes and not a Markdown table; this tool doesn’t produce it.

Tables on GitHub

GitHub renders the GFM tables extension. GitHub Docs say to leave a blank line before the table, and that cells can hold formatting such as links, inline code and text styling. The spec says block-level elements can’t be inserted in a table, so a cell can’t hold a list or a code block, and a raw newline would end the row. For a line break inside a cell, use <br>: the spec’s raw HTML rules allow it, and its tag filter lists only title, textarea, style, xmp, iframe, noembed, noframes, script and plaintext.

Keep table diffs small in Git

If your notes live in Git, the output style matters. In an aligned table every cell in a column is padded to the longest one. Change “Open” to “In progress” and the whole column gets wider, so every row changes:

-| Task          | Status |
-| ------------- | ------ |
-| Book the room | Open   |
-| Send agenda   | Done   |
+| Task          | Status      |
+| ------------- | ----------- |
+| Book the room | In progress |
+| Send agenda   | Done        |

The same edit in a compact table touches one line:

 | Task | Status |
 | --- | --- |
-| Book the room | Open |
+| Book the room | In progress |
 | Send agenda | Done |

That makes reviews and merge conflicts smaller too: two people editing different rows of a compact table don’t touch the same lines. The trade-off is that the raw text is harder to read. If the note is mostly read as plain text, choose Aligned. To see what a change looks like, paste both versions into the Markdown diff tool.

Frequently asked questions

Can a Markdown table have merged cells?

No. The GFM spec has no syntax for merged cells or for block content in a cell. Repeat the value, leave the cell empty, or split the table in two.

How do I put several lines in one cell?

A table row has to stay on one line, so write a <br> tag where the line break goes. GFM allows raw HTML and does not filter <br>, so GitHub renders it. This tool converts line breaks to <br> for you.

How do I convert CSV to a Markdown table?

Paste the CSV into the import box and press Import. The tool detects CSV, reads quoted fields the way RFC 4180 describes (commas and doubled quotes inside quotes), and fills the grid. Cells copied from Excel, Google Sheets or Numbers arrive as tab-separated text and are detected the same way. You can override the detected format.

Does Obsidian need a plugin for tables?

No. Obsidian’s Help describes the pipe and hyphen syntax as part of its Markdown, and Live Preview has a context menu for rows and columns. Plugins are optional.
