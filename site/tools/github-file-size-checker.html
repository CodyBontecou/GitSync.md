GitHub’s size limits

These come from GitHub’s documentation: About large files on GitHub and About Git Large File Storage. The checker uses binary units (1 MiB = 1,048,576 bytes).

What to do with each flagged file

  • Track it with Git LFS. Git LFS replaces the file in your repository with a small pointer and stores the real bytes separately. Use the .gitattributes lines the checker generates, or run git lfs track "*.mp4". Do it before you commit the file. Project site: git-lfs.com.
  • Ignore it. If the file doesn’t need to travel with the repository (a render, a download, a build output), add it to .gitignore and keep it on one device.
  • Compress it. A video re-exported at a lower bitrate, a PDF run through a compressor or an image saved at a sensible size can come under the limit.
  • Keep it out of the vault. Store big media in a folder outside the repository and link to it from your notes.

Already committed a big file?

Ignoring or LFS-tracking a file now does not change commits that already contain it. If a push still fails after you removed the file from your folder, an older commit probably holds it. On a computer, this lists the biggest objects in all of your history, largest last:

git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '$1 == "blob" && $3 > 50*1024*1024' \
  | sort -k3 -n

That prints blobs over 50 MiB with their sizes and paths. To remove a file from history, follow GitHub’s docs: Removing files from Git Large File Storage and Removing sensitive data from a repository. Rewriting history changes commit IDs, so everyone with a clone has to re-clone or reset.

Obsidian vaults and big attachments

Notes are tiny. What breaks a push is attachments: screen recordings, exported videos, long audio recordings, scanned PDFs and zip archives. A single file past 100 MiB is enough to block a push, and one past 50 MiB makes Git warn. Decide per file type: LFS for what you want on every device, .gitignore for what you don’t. Frequently asked questions

What is GitHub's file size limit?

GitHub blocks files larger than 100 MiB and warns about files larger than 50 MiB. Files you add through the browser on github.com are limited to 25 MiB. Larger files can be stored with Git Large File Storage (Git LFS), which has its own per-file maximum that depends on your plan.

Is there a repository size limit?

GitHub's documentation recommends keeping repositories ideally under 1 GB and strongly recommends staying under 5 GB. That is guidance rather than a hard cap, but big repositories are slower to clone, especially on a phone.

Can I push files over 100 MB?

Not as regular Git files. GitHub blocks them. Track the file with Git LFS, which stores the real bytes outside the repository, or keep the file out of the repository. If the file is already in your history, you also have to remove it from the commits that contain it.

Is my vault uploaded?

No. This page reads file names and sizes with your browser's File API and does no network requests. File contents are never read, and nothing leaves your device or is saved.

Does this check my Git history?

No. It measures the files as they are on disk now. A large file that you committed earlier and later deleted can still be in history and make a push fail. See the history section below for the command that finds those.
