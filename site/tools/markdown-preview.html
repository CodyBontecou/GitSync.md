What changes on GitHub

Obsidian syntax that GitHub doesn’t render

GitHub renders GitHub Flavored Markdown, plus a few extras its docs describe: alerts, task lists and footnotes. Obsidian adds its own syntax on top of Markdown. When a vault is pushed to GitHub, that extra syntax shows as typed.

Obsidian syntaxGitHub showsFix if you publish the vault
[[Note]], [[Note|display text]], [[Note#Heading]]The literal text, not a link.Use Markdown links: [Note](Note.md), with spaces in the file name written as %20. In Obsidian, open Settings → Files and links and turn off “Use [[Wikilinks]]” so new links are Markdown links. Obsidian’s Help doesn’t say whether existing wikilinks are converted, so check a note after you change it.
![[image.png]], ![[Note]]The literal text. Nothing is embedded.For an image, use ![alt](image.png). A note embed has no Markdown equivalent, so replace it with a link to the note.
Callouts: > [!abstract], > [!tip]- TitleA plain block quote with the [!…] marker as text. GitHub only turns five types into alerts: NOTE, TIP, IMPORTANT, WARNING and CAUTION.For those five, write the marker alone on the first line, as in > [!NOTE]. Obsidian’s fold markers (-, +) and custom titles have no GitHub equivalent. Obsidian styles [!important] like tip and [!caution] like warning, so colors differ between the two.
==highlight==The literal text with the equals signs.Remove the equals signs, or switch to **bold** or *italic*. The GitHub Docs page on formatting syntax doesn’t list a highlight syntax.
%%comment%%The comment text shows on the page.Use <!-- comment -->. Obsidian’s Help recommends it for other apps, and GitHub Docs say it hides content from the rendered Markdown.
#tagPlain text.Nothing breaks and the text stays readable, but GitHub doesn’t style it as a tag.
Front matter (Properties)A table of the keys and values at the top of the file.Keep it if the table is fine for readers, or remove it from notes you publish. To check the properties themselves, use the Obsidian frontmatter checker.

Convert Markdown to HTML

The HTML source tab shows the GitHub-flavored output for your note. Copy HTML puts exactly that text on your clipboard. Download .html saves a complete page (with <!doctype html>, a <title> taken from the first H1, and the same body) from a Blob in your browser, so no server is involved.

By default the HTML has no styles, so it picks up the styles of wherever you paste it. Tick “Include a minimal style block” to add a short <style> block with readable defaults for text, tables, code and alerts. The output follows GitHub rather than Obsidian: tables, task lists, strikethrough, footnotes, alerts and front matter as a table. Obsidian-only syntax stays as typed, as in the GitHub preview. Images become <img> tags with the URL you wrote. Raw HTML, Mermaid and math are output as escaped code blocks, not rendered, so the converter never passes your HTML through.

Frequently asked questions

Does this upload my note?

No. The page has no external scripts and makes no network requests while you use it. Pasted text and opened files are read in your browser, nothing is saved, and the download is created locally. After the page has loaded, it keeps working offline.

Why do my wikilinks show as text on GitHub?

[[Note]] is Obsidian syntax. It isn’t part of the GitHub Flavored Markdown spec, so GitHub shows the brackets as typed. Obsidian’s Help describes the Markdown form, [Text](Note%20Name.md), and the setting Files and links → “Use [[Wikilinks]]” that makes Obsidian write that form.

Does GitHub support Obsidian callouts?

Only five of them. GitHub Docs list the alert types NOTE, TIP, IMPORTANT, WARNING and CAUTION, written as > [!NOTE]. Other Obsidian types such as abstract or question, fold markers and custom titles show as a plain block quote.

Can I convert Markdown to HTML offline?

Yes. Load this page once, and conversion, Copy HTML and Download .html all run in your browser without a connection.
