Short version
  1. Standard Markdown (headings, lists, links, tables, task lists, footnotes, math, Mermaid) works in both.
  2. Obsidian-only syntax ([[wikilinks]], ![[embeds]], ==highlights==, %%comments%%, block references) isn't in GitHub's syntax docs. Expect plain text on github.com.
  3. Callouts and GitHub alerts share > [!NOTE]. Stick to the five GitHub types, with no title and no fold marker, and it works in both.

Obsidian says it supports CommonMark, GitHub Flavored Markdown and LaTeX, then adds its own extensions (Obsidian Flavored Markdown). GitHub renders GitHub Flavored Markdown (GFM spec), which does not include those extensions. Obsidian's own page warns that other Markdown apps may show internal links, comments and highlights as plain text. This page turns that warning into a lookup: the first column is the code to copy.

Line breaks

A blank line starts a new paragraph in both. For a line break inside a paragraph, the sources differ:

  • GitHub, in .md files: end the line with two spaces, a backslash, or <br/>. (In issues, pull requests and discussions, a single newline is already a line break.)
  • Obsidian: end the line with two spaces, or press Shift+Enter. With the Strict line breaks setting on, a single Enter joins lines unless the line ends with two spaces.

The two-space break is the one both sources document, so use it when a note must read the same in both places.

Task lists and checkboxes

The answer to “how do I make a checkbox in Markdown”: start a list item with - [ ] for an open box or - [x] for a checked one, with a space after the hyphen and inside the brackets.

- [ ] Write the draft
- [x] Outline the post
Task lists
Syntax (copy this)ObsidianGitHub (.md files)
- [ ] to do - [x] done✓ Yes. Click the box in Reading view.✓ Yes. GitHub documents task lists in comments; the GFM spec defines them for any Markdown.
- [/] in progress✓ Obsidian accepts any character in the brackets (the Help page shows [?] and [-]). How it looks depends on your theme or plugins.✗ Not portable. GitHub’s documented task syntax is [ ] and [x].

GitHub's About task lists describes tasklists in comments. Whether you can tick a box in a rendered repository file isn't covered there, so this guide makes no claim about it. If you tick boxes in Obsidian and push, the change is the [ ] to [x] text edit in your commit.

Callouts vs GitHub alerts

Obsidian callouts and GitHub alerts both start a blockquote with [!type]. They are different features with different type lists. Obsidian's Callouts page and GitHub's alerts section (in the syntax docs) say:

  • GitHub has five types: NOTE, TIP, IMPORTANT, WARNING and CAUTION. The marker goes on its own line, followed by the message in the blockquote. GitHub says alerts can't be nested in other elements.
  • Obsidian has more: note, abstract, info, todo, tip, success, question, warning, failure, danger, bug, example and quote, plus aliases. Types are case-insensitive, and an unknown type falls back to note. It also supports a custom title after the marker (> [!tip] My title), fold markers ([!faq]- collapsed, [!faq]+ expanded) and nested callouts.
The five GitHub alert types in both apps
GitHub alertIn ObsidianOn GitHub
[!NOTE]✓ Same type, note.✓ [!NOTE]
[!TIP]✓ Same type, tip.✓ [!TIP]

Custom titles, fold markers and the other Obsidian types aren't part of GitHub's documented alert syntax, so don't count on them rendering as a callout on github.com. A callout with an Obsidian-only type is, at best, a plain blockquote there.

A portable callout

Use one of the five GitHub types, put the marker alone on its line, and skip the title and fold marker:

> [!NOTE]
> Plain text on the line below the marker.
> Add [a normal link](other-note.md) and **bold** if you like.

On GitHub it is an alert. In Obsidian it is a callout. With IMPORTANT or CAUTION, Obsidian shows the tip or warning style instead.

Properties and frontmatter

Obsidian stores properties as YAML at the top of the note, between --- lines. In Settings → Editor → Properties in document you choose Visible (the default), Hidden or Source, which shows the raw YAML. Tags can be a property too: a tags list with one hyphenated item per line.

---
title: Trip notes
tags:
  - travel
  - draft
---

# Trip notes

To Git it is ordinary text at the top of the file, so it commits, diffs and merges like any other line. Use the Markdown diff tool to compare two versions of a note, and see merge conflicts on iPhone if both sides edited the same properties.

Links that work in both

Obsidian treats wikilinks and Markdown links as equivalent, and uses wikilinks by default. To write standard Markdown links instead, open Settings → Files and links and turn off Use [[Wikilinks]]. Typing [[ still autocompletes, but inserts a Markdown link.

Spaces need handling: Obsidian's Help page says to write %20 for each space, or wrap the destination in angle brackets. GitHub resolves relative paths from the current file, and ../ works.

[Meeting notes](Meeting%20notes.md)
[Meeting notes](<Meeting notes.md>)
[Plan](../Projects/Plan.md)
![Diagram](attachments/diagram.png)

The first two links point to the same file and differ only in how they handle the space: %20 is the form Obsidian's Help page documents, and angle brackets are valid link-destination syntax in CommonMark. Keep link text on one line, because GitHub's docs say so.

Checklist: make a vault readable on GitHub

  1. Turn off Use [[Wikilinks]] so new links are Markdown links.
  2. Replace ![[image.png]] with ![alt](attachments/image.png), and keep attachments in a folder inside the repository.
  3. Skip ==highlights== and %%comments%% in notes that GitHub readers will see, or accept the stray characters. Use <!-- --> for hidden text.
  4. Use [^1] footnotes, not ^[inline].
  5. Write callouts with the five GitHub types and no title.
  6. Keep the .obsidian folder and private files out of a public repo with the Obsidian .gitignore generator.

FAQ

Does GitHub support Obsidian wikilinks?

Wikilinks are not in GitHub's syntax docs. Obsidian's Help warns that other Markdown apps may show internal links as plain text. Use Markdown links to be safe.

Are Obsidian callouts the same as GitHub alerts?

They share the > [!type] start but are different features. GitHub documents five alert types. Obsidian has more types, custom titles and fold markers. The portable callout above works in both.

How do I make a checkbox in Markdown?

Write - [ ] task for an open box and - [x] task for a checked one. Both Obsidian and GitHub understand that syntax.

Why do my images not show on GitHub?

The usual cause in a vault is ![[image.png]], an Obsidian embed that isn't in GitHub's syntax docs. Use ![alt](attachments/image.png) with a path relative to the note, and make sure the image file is committed and pushed.
