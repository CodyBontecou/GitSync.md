Obsidian Git not working on iPhone? Start here.

Check the local vault folder first, then test authentication in the app that reported the error. GitSync.md and Obsidian Git share files, but each runs its own Git operations. A successful sign-in in one app does not prove the other can push.

October 26, 2026By Cody BontecouiPhone + iPad
Find your symptom
  1. The vault is missing
  2. No Git repository found
  3. Pull or push cannot authenticate
  4. Commit author is missing
  5. Connect does not start
  6. Changes conflict or push is rejected
  7. Automatic sync did not run
The quick check
  1. Open the repository in GitSync.md and confirm it is cloned.
  2. Open that exact folder as the vault in Obsidian. A parent folder or a second copy of the notes is a different working copy.
  3. Read the error in the app performing the operation. Check folder access, credentials, author identity, and branch state separately.
  4. Test a manual pull and push before enabling automation.

This guide covers the GitSync.md workflow on iOS 17 or iPadOS 17 and later. Connect requires GitSync.md 2.8.0 or later; use 2.8.1 or later for a vault created with Publish a Folder. The companion and Obsidian Git are separate community plugins.

Starting from scratch? Follow how to sync Obsidian with Git on iPhone and iPad. GitSync.md costs $19.99 once on the US App Store; regional prices vary. If you already own it, work through the matching symptom below.

Obsidian does not show the cloned vault

Confirm the clone destination in GitSync.md. For the documented local setup, the repository belongs under On My iPhone → Obsidian or On My iPad → Obsidian. Check that the clone completed and the folder contains your notes.

  1. Fully close and reopen Obsidian after cloning.
  2. Use the vault picker to open the cloned folder.
  3. Check that you did not open a parent folder containing the real vault one level deeper.

If Obsidian’s local folder is missing in Files, create a local vault in Obsidian first with Store in iCloud turned off. Then return to the folder picker in GitSync.md. See the folder setup walkthrough.

Obsidian Git says no Git repository was found

The notes and the Git working copy must be in the same folder. Copying Markdown files into a new vault does not necessarily copy the hidden .git directory containing Git history and configuration.

  • Check that GitSync.md recognizes the same folder as a cloned or managed repository.
  • Open the repository root as your Obsidian vault, rather than a subfolder or its parent.
  • For Connect, use a regular .git directory at the vault root. Custom Git directory paths, base paths, and alternate push destinations are outside that connection flow.

If your notes have never been in Git, publish the local vault with GitSync.md or create and push the repository on desktop first. Preserve unsynced edits before replacing a working copy. Deleting .git is not a setup repair.

Pull or push fails even though GitSync.md is signed in

First identify which app failed. GitSync.md stores its native credentials in Keychain. Obsidian Git needs its own configured credentials when it performs operations inside Obsidian.

  • GitSync.md fails too: check the selected account, remote URL, repository access, and authentication method there. For SSH, check the key, passphrase, host, and port. Follow the SSH and HTTPS troubleshooting steps.
  • Only Obsidian Git fails: for a supported GitHub HTTPS vault, use GitSync.md Connect or configure a GitHub Personal Access Token manually.
  • Connect worked before a token expired or account changed: authenticate the intended account in GitSync.md, then run GitSync.md Connect: Reconnect this vault (replace existing Git credentials) in Obsidian. Automatic connection preserves existing credentials; imported tokens do not refresh in the background.

Connect supports GitHub HTTPS repositories using GitSync.md’s GitHub Account authentication. It does not add support for SSH, other Git hosts, or separate per-repository HTTPS tokens to Obsidian Git. You can use GitSync.md itself for those Git operations while editing the local notes in Obsidian.

“Git author name and email are not set”

A Git author identifies a commit; a token authenticates a network request. Setting one does not replace the other.

In Obsidian Git’s settings, fill in Author name and Author email, then retry the commit. Connect can fill missing author fields from GitSync.md, but you should still verify the values you want on your commits. See the manual author setup.

GitSync.md Connect does not start or cannot finish

  1. Update GitSync.md. Version 2.8.1 fixes connecting vaults created with Publish a Folder.
  2. Install and enable both Git by Vinzent and GitSync.md Connect inside this vault. Repeat plugin installation in each vault you connect.
  3. Open the repository in GitSync.md once, return to Obsidian, then run GitSync.md Connect: Connect this vault. Reopen the vault if Git is still initializing.
  4. If saved credentials need replacing, choose the explicit Reconnect this vault (replace existing Git credentials) command.

A connection response expires after five minutes. If app switching was interrupted, run Connect this vault again rather than copying temporary files. The Connect tutorial shows the complete sequence and the expected confirmation.

Pull reports local changes, or push is rejected

For a file-by-file example, follow the iPhone merge-conflict recovery guide.

These messages are not always credential failures. A pull can stop because local files changed. A push can be rejected because the remote has commits your phone does not have, or because the server enforces a repository policy. Read the reported reason before retrying.

  1. Keep a separate copy of unsynced notes and review the local diff.
  2. Open the repository in GitSync.md and inspect the current branch and remote state.
  3. If histories diverged or conflicts exist, use the manual merge or rebase workflow. The Conflict Center lets you choose ours, theirs, or an edited result. Review each affected file before completing the operation.
  4. Retry the push only after the working copy is in a state you understand. For unfamiliar history, finish on desktop using the same repository.

GitSync.md’s automatic pulls only accept clean fast-forwards. They stop for local edits or divergence instead of resolving conflicts. Repeated authentication changes or deleting and recloning the vault will not reconcile different edits.

Automatic sync did not run

The background-sync guide explains each automation path and the settings that control it.

Connect configures authentication. It does not turn on sync intervals. Obsidian Git’s timers, GitSync.md Background Sync, and Apple Shortcuts are separate automation paths.

Test a manual operation first. Then check the settings for the automation you chose, including repository exclusions, automatic pull, separately enabled publishing, and network or power policies. iOS decides when background execution is allowed; timing is not guaranteed. A newly published folder starts excluded from Background Sync.

For an explicit trigger, follow the Apple Shortcuts guide. Avoid overlapping timers from multiple Git clients on the same folder while diagnosing the problem.

Confirm the repair in both directions

  1. Create a disposable test note on another device and push it. Pull on the phone and open the note in Obsidian.
  2. Edit the note on the phone, commit, and push using your chosen Git client.
  3. Check the exact contents and the new commit on GitHub or your Git server.

If you need help, report the app and plugin versions, the failing step, and a redacted error message. Do not include tokens, private repository URLs, or personal notes.
