Short answer

Yes. A Logseq graph that is a folder of Markdown or Org files can live in a private Git repository, and you can edit it on iPhone or iPad by cloning that repository with GitSync.md into a folder the Logseq app can open, then committing and pushing from the phone and pulling on the computer. You need a Git remote (such as a private GitHub repository), Git on your computer and the two apps. This works only for file graphs, not Logseq's newer database (DB) graphs.

Before you start: file graphs vs DB graphs

Checked November 2026

In its announcement dated April 24, 2026, Logseq says it is splitting into two products: file-based Markdown graphs go to Logseq OG, and database graphs stay in Logseq. Git syncs plain files, so this guide applies to file graphs. The logseq/logseq repository describes the DB version and its DB graphs, and its releases page lists what shipped. Check both before you pick a version; this page doesn't predict what Logseq will add.

How to tell which you have: a file graph is a folder you can open in Files or a file manager and see .md (or .org) files in it, as the Logseq App Store listing describes for local files. If your graph lives in Logseq's database instead of as a folder of pages, Git can't sync it with this method. Logseq says Markdown in the DB version is something it is still researching.

What's in a Logseq graph folder

A file graph is a normal folder. These are the names in a default graph, and what to do with each in Git. The commit/ignore advice is this guide's recommendation, not an official Logseq rule:

PathWhat it isIn Git?
pages/Your pagesCommit
journals/Daily journal files, one per dayCommit
assets/Images and attachments you addedCommit (large files: see Git LFS on iOS)
logseq/config.ednGraph settingsCommit, so devices share settings
logseq/custom.cssYour custom stylesCommit
logseq/bak/Automatic backup copies of pagesIgnore: Git history already keeps versions
logseq/.recycle/Deleted pages moved asideIgnore, or keep if you want deletions recoverable on every device

For prior art on the desktop workflow, see the community Logseq-Git-Sync-101 wiki. For iOS it points to other apps; this guide covers GitSync.md.

Step 1: Create a private repository and push from the computer

One repo, set up once

  1. Create an empty private repository on your Git host. On GitHub, follow Creating a new repository and choose Private.
  2. In your graph folder, add a .gitignore (below), then initialise and push: 
    cd /path/to/your-graph
git init -b main
git add .
git commit -m "Initial commit of my Logseq graph"
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main

A sample .gitignore for a Logseq file graph (see gitignore docs):

# Logseq: automatic page backups (Git history replaces them)
logseq/bak/
# Logseq: deleted pages
logseq/.recycle/
# Per-device and OS files
.DS_Store
Thumbs.db
*.swp

If you'd rather not commit by hand, Logseq on desktop has an automatic Git commit option in its settings, with a commit interval; look for it in Logseq's settings and check its own docs, as labels vary between versions. It only commits on the computer. You still need to push, with git push or a scheduled job of your own. Related tool, not Logseq-specific: the Obsidian .gitignore generator.

Step 2: Clone the graph on iPhone or iPad with GitSync.md

Install GitSync.md and clone

  1. Install GitSync.md from the App Store.
  2. Sign in to GitHub with OAuth or a personal access token, or use another HTTPS or SSH remote such as GitLab, Gitea or Forgejo (self-hosted Git over SSH).
  3. Choose a save location that is a folder the editor can open, a local folder in Files such as under On My iPhone, not an iCloud-backed one. Don't assume a specific Logseq folder path; use one you can browse to from Logseq.
  4. Clone your repository. The clone guide has detailed steps.

Step 3: Open the cloned folder as a graph in Logseq on iOS

In the Logseq app, add or open a graph from a local folder and pick the folder GitSync.md cloned. The App Store listing describes the app as working with local files; the exact menu wording changes between versions, so follow Logseq's own prompts. Choose the repository root (the folder that holds pages/, journals/ and .git).

Avoid iCloud-backed folders

Git and a folder that iCloud syncs can fight over the same files. See iCloud vs Git for why.

Step 4: Daily loop and round-trip check

The simple rule that avoids most conflicts: pull before you edit, push after (git pull).

Phone to computer

  1. In GitSync.md, pull.
  2. In Logseq, add one line to a synthetic journal, for example journals/2026_11_22.md: - Test from iPhone
  3. In GitSync.md, review the diff, commit and push.
  4. On the computer, run git pull and confirm the line is in the file: 
    git pull
grep "Test from iPhone" journals/2026_11_22.md

Computer to phone

  1. On the computer, add - Test from desktop to the same file, then git add -A && git commit -m "Test from desktop" && git push.
  2. In GitSync.md, pull, then open the page in Logseq and look for the line. If Logseq doesn't show it, see troubleshooting.

Delete the test lines afterwards.

Automate the phone side

GitSync.md has Pull, Push and Sync actions in Apple Shortcuts; see the Shortcuts guide. iOS decides when background work runs, so don't count on it: read the background sync guide for the limits.

Conflicts

The most common case is a journal edited on two devices on the same day. GitSync.md's Conflict Center lets you choose ours or theirs, or edit a merged result in a three-way view, then continue or abort the merge or rebase. Steps are in the merge-conflicts guide, which is written for Obsidian but the Git side is the same.

Troubleshooting

Logseq doesn't show new pages after a pull

Close and reopen the graph first. Logseq has its own re-index option for rebuilding a graph from its files; look for it in Logseq's graph menu and check Logseq's docs for your version. First confirm the files arrived: open the folder in Files.

Desktop commits but never pushes

Logseq's automatic Git option only commits. Push with git push, or the phone will never see the changes.

Authentication fails

For GitHub, re-sign in, or create a new token with access to the repository (token docs). See the clone guide.

Wrong folder

If Logseq shows an empty graph, you probably opened a parent or sub-folder. Open the folder that contains .git.

FAQ

Is Git a replacement for Logseq Sync?

They're different tools. Git gives you explicit commits, history and your own remote, and you pull and push yourself. For Logseq's own sync service, see Logseq's documentation.

Does this work with DB graphs?

No. Git syncs plain files, and DB graphs are database graphs, not a folder of Markdown pages (Logseq's announcement).

Does it work on Android?

GitSync.md is on Google Play. We haven't tested Logseq steps there; Obsidian Git on Android is a general pointer for Git on Android.

Is it free?

Git, GitHub private repositories and Logseq have their own terms. GitSync.md on iPhone and iPad is $9.99 once, with no subscription.
