What the Obsidian Git plugin does

The Obsidian Git community plugin runs Git for your vault: commit, pull and push, plus a source control view, a history view and a diff view. Its docs use commit-and-sync for the whole routine: stage, commit, pull, then push. The older name for it was “backup”, which the docs now mark as no longer in use.

Git suits asynchronous editing: you change a note on one device, commit, and pick the change up on another. It isn’t live co-editing, so two devices editing the same lines between syncs produce a conflict.

Install and first repo

Install it from Settings → Community plugins → Browse, as described in Obsidian’s help. There are three ways to start, from the plugin’s Getting Started page:

  • You already have a repository. If the vault folder is a Git repository, the plugin uses it.
  • New repository. Run Git: Initialize a new repo, make a first commit with Git: Commit all changes, set up authentication, then push to a remote named origin.
  • Clone. Git: Clone an existing remote repo exists, but the docs note that Git can only clone into a new folder. Clone into a subfolder of the vault and move the files up, open the subfolder as its own vault, or run git clone in a terminal where you want the vault.

For the full walkthrough with GitHub, including the repository, authentication and phone setup, follow Sync Obsidian with GitHub on every device. This page doesn’t repeat it.

Views: source control, history, diff and line authoring

  • Source control view lists changed files so you can stage, unstage, discard and commit them.
  • History view shows the commit log. Its settings let you show the author as full name or initials and show the date.
  • Diff view compares versions of a file. The settings offer split or unified style (marked desktop in the plugin’s settings).
  • Line authoring shows who last changed each line, based on git blame. The docs say only Obsidian on desktop is supported, and it works in Live Preview and Source mode, not Reading mode. Toggle it with Git: Toggle line author information.

Settings explained by job

Instead of every toggle, here are the ones that decide how the plugin behaves, grouped by what you want. The names follow the plugin’s current settings code. For recommended values, see the settings table in the GitHub guide.

Sync on a schedule

  • Auto commit interval (minutes): commits on a timer. 0 turns it off. With separate intervals off, the label reads “commit-and-sync”, and the timer also pulls and pushes.
  • Auto commit-and-sync after stopping file edits: waits until you stop typing. It needs a non-zero interval.
  • Use separate commit and push intervals: adds Auto push interval (minutes).
  • Pause/Resume automatic routines: a command, for when you want a quiet hour.

Pulling

  • Pull on startup: pulls when Obsidian opens.
  • Auto pull interval (minutes): pulls on its own timer.
  • Pull on commit-and-sync and Push on commit-and-sync: turn off pushing and commit-and-sync becomes a local commit.
  • Merge strategy: Merge, Rebase, or Other sync service (update HEAD only). Marked desktop in the settings, and the README lists no rebase on mobile.
  • Merge strategy on conflicts: None (Git default), Our changes or Their changes.

Commit messages

  • Commit message on auto commit-and-sync and Commit message on manual commit accept placeholders such as {{date}} and {{hostname}}.
  • {{date}} placeholder format takes a Moment.js format; {{hostname}} placeholder replacement sets a short name for this device.
  • Preview commit message shows the result before you rely on it.

Per device (Advanced)

  • Disable on this device: turns the plugin off on one device. The setting is not synced, so other devices keep their own.
  • Custom Git binary path (desktop): where to find Git if it isn’t on your PATH. See the error table below.
  • Additional PATH environment variable paths (desktop): extra folders for Git to search.
  • Repository folder within the vault: use it if the repository isn’t at the vault root.
  • Username on your Git server and Git server password or access token appear on mobile.

Desktop vs mobile

The README calls mobile support experimental and says the Git implementation on mobile is very unstable. On mobile the plugin can’t run a native Git program. It uses isomorphic-git, a JavaScript implementation, so some features are missing.

When to use a native Git app on your phone instead

The plugin is the right tool on desktop. On a phone it can be enough for a small vault over HTTPS. A native Git client is the better choice when the vault is large, the remote needs SSH, or Obsidian crashes during clone or pull. The plugin’s own docs say that if mobile crashes happen to you, the plugin won’t work for you.

Obsidian Git on iOS: options and setup, including GitSync.md on iPhone and iPad (iOS and iPadOS 17 or later) and on Android (Android 9 or later) does Git natively over HTTPS or SSH, in the folder Obsidian opens. GitSync.md Connect (needs GitSync.md 2.8.0 or later) passes a GitHub sign-in to the plugin for HTTPS vaults. It doesn’t lift the plugin’s mobile limits.

If GitSync.md handles Git on the phone, turn on Disable on this device in the plugin there, so two Git clients don’t work on the same folder. GitSync.md is not the open-source “GitSync” app the plugin’s README may mention; see GitSync vs GitSync.md. To weigh Git against Obsidian’s own service, read Obsidian Sync vs Git.

FAQ

Is the Obsidian Git plugin free?

The plugin is a free community plugin, and Git itself is free. Your Git host’s plans are separate.

Does it work on iPhone?

Yes, with limits. The README marks mobile support experimental. It can work for a small vault over HTTPS and may crash on larger ones.

Does it support SSH on mobile?

No. The README lists no SSH authentication on mobile. Use HTTPS with a personal access token, or a native Git client.

Why does it keep pulling or pushing forever?

The docs say infinite pulling or pushing with no error is usually an authentication problem. On mobile, the docs also list running indefinitely among the performance problems.

Can I use it with GitLab?

Git works with any remote, so yes. See Sync Obsidian with GitLab for tokens and host keys.
