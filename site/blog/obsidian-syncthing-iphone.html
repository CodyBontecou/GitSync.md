Obsidian with Syncthing on iPhone and iPad.

There is no official Syncthing app for iOS. Here are the third-party apps, how to set one up next to Obsidian, the limits you will hit, and when Git is the simpler route for the phone.

Short answer

Syncthing has no official iOS app, and its Syncthing FAQ says iOS background limits make it very hard to run reliably. Two third-party apps exist: the open-source Synctrain and the commercial Möbius Sync. Both sync best while the app is open, and the other device must be online at the same time. Whether Obsidian can open the folder they sync is something to test on your own phone; no Obsidian or app documentation describes the route. If that becomes a chore, sync the phone with Git instead.

What you need

  • Syncthing running on a computer that holds your vault. See Syncthing’s getting-started guide.
  • An iOS Syncthing client from the list in step 1.
  • Obsidian for iOS. Obsidian’s sync help lists Syncthing as recommended for Windows, macOS and Linux and as not officially supported on iOS, so treat this as a community setup and keep a backup of the vault.

Step 2: Pair the iPhone with your desktop

Per Syncthing’s getting-started guide, two devices only connect if each is configured with the other’s device ID. Find the ID in the desktop web GUI under Actions → Show ID, add it as a remote device in the iOS app, then add the phone’s ID on the desktop. Devices usually connect after a minute or so. The iOS apps’ own screens differ, so follow each app’s documentation for where its device ID is shown.

Step 3: Share the vault folder and open it in Obsidian

On the desktop, share the vault folder with the phone as in the getting-started guide, and accept it in the iOS app. Then the hard part is the iOS sandbox. Two facts are documented:

  • Obsidian on iOS keeps local vaults in its own folder, On My iPhone → Obsidian, or in iCloud Drive → Obsidian (see our Git setup guide and Obsidian’s sync help).
  • The sync apps write into their own folders, which they show in the Files app (Synctrain’s Documents directory; Möbius Sync’s Open Folder button).

I found no Obsidian, Synctrain or Möbius Sync documentation that says an iOS Syncthing client can write straight into Obsidian’s folder, or that Obsidian can open a synced folder from another app. Möbius Sync’s App Store changelog mentions support for user-created folders under “On my iPhone”, which is the area Obsidian uses, but it doesn’t say how to point a folder at Obsidian’s. So:

  1. Try with a throwaway vault first, not your real notes.
  2. In the sync app, look for a way to choose where a shared folder is stored. If it offers one, read that app’s documentation before using it.
  3. In Obsidian’s vault picker, try Open folder as vault (the option our Git guide uses) and see whether the synced folder is selectable.
  4. If the folder isn’t selectable, stop. Don’t copy files back and forth by hand as a sync method; that is the situation where duplicate and overwritten notes happen.

Step 4: Test a round trip

  1. On the phone, create a note named sync-test.md with the text “from phone”. Open the sync app so it can run.
  2. On the desktop, wait for sync-test.md to arrive. Syncthing’s web GUI shows the folder as up to date when it has.
  3. Edit it on the desktop to add “from desktop”, then open the sync app on the phone and check Obsidian shows both lines.
  4. Only then move real notes in. Turn on versioning on the desktop folder first (see below).

Recommended ignore patterns

Syncthing reads ignore patterns from a .stignore file in the root of the synced folder, and each device uses its own copy (it isn’t synced). The first matching pattern wins, and lines starting with // are comments. See Syncthing’s ignore docs and check this example against them before use. It is an example, not a rule set.

// Example .stignore for an Obsidian vault
// Obsidian layout state that changes when you open or move notes
.obsidian/workspace.json
.obsidian/workspace-mobile.json
// Obsidian's default trash folder, if you don't want deletions copied around
.trash/
// Git internals, if the same folder is also a Git working copy
.git/
  • workspace.json and workspace-mobile.json: stop open-pane layout from being overwritten between desktop and phone. Our Obsidian .gitignore guide treats them as device-specific for the same reason.
  • .trash/: keeps Obsidian’s trash from syncing. Leave it out if you want deletions recoverable on every device.
  • .git/: keeps repository internals off devices that don’t need them.

For the Git equivalent, use the Obsidian .gitignore generator.

What goes wrong on iOS and how to fix it

Notes don’t appear

Syncthing exchanges changes “as soon as they are online at the same time” (the Syncthing FAQ), and there is no server copy. On iOS the sync app also has to get run time: open it and keep it in the foreground until the folder shows as up to date. Möbius Sync’s FAQ says iOS may not run it in the background for hours.

.sync-conflict files

When both devices change a file while apart, Syncthing keeps both and renames the older one to name.sync-conflict-<date>-<time>-<modifiedBy>.md, per conflict handling. Syncthing doesn’t pick a winner for you: open both notes, copy what you want into one, and delete the other. Git’s version is in the Git conflict guide.

No safety net by default

File versioning is off by default, so a deleted or overwritten note is gone on every device unless you enable Trash Can, Simple or Staggered versioning on a folder.

Duplicated or empty vault

If Obsidian shows an empty vault, you probably opened the wrong level or a folder that hasn’t finished syncing. If you see a second copy, you may have created a new vault next to the synced one. Check the folder in the Files app before you write anything.

Plugins differ between devices

Obsidian keeps plugin and settings data in each vault’s .obsidian folder. Syncing it moves plugin settings too, and mobile and desktop can have different plugins. Ignore what you don’t want shared, and install plugins on each device.

Keep Syncthing on desktop, use Git for the phone

One pattern you can choose: a desktop vault folder that Syncthing syncs between computers can also be a Git working copy pushed to a remote, and the phone uses GitSync.md against that remote. GitSync.md does not talk to Syncthing; it only talks to the Git remote. Two sync systems on one folder need care:

  • Commit or pull only while Syncthing is idle.
  • Put .git/ in .stignore so repository internals aren’t copied to devices that don’t need them.
  • Obsidian advises one sync method per vault; read the sync help first.

FAQ

Is there an official Syncthing app for iPhone?

No. The Syncthing FAQ says the team has no plans to officially support iOS in the foreseeable future. It points to two third-party apps: the open-source Synctrain and the commercial Möbius Sync.

Does Syncthing sync Obsidian in the background on iOS?

Not reliably. The Syncthing FAQ says iOS restrictions on background processing make it very hard to run Syncthing reliably. Möbius Sync’s FAQ says iOS lets apps run in the background only for short, sporadic periods, and Synctrain’s README says it supports background sync “to the extent possible”. Open the sync app before you switch devices.

Is Syncthing better than iCloud for Obsidian?

It depends on your devices. Obsidian’s help recommends iCloud and Obsidian Sync on iOS and lists Syncthing as not officially supported there. Syncthing needs no cloud account and works with Windows, Linux and Android, but on iPhone it relies on a third-party app and iOS background limits. iCloud covers Apple devices only.

Can I use Syncthing and Git on the same vault?

It is possible, but it needs care. Two systems that rewrite the same folder can create conflicts. If you try it, add .git/ to .stignore, and commit or pull only while Syncthing is idle. Check Git’s and Syncthing’s documentation before you rely on it.

Recap

Syncthing can sync a vault to an iPhone only through third-party apps, and with iOS background limits. Pair the devices, test with a throwaway vault, ignore workspace files, turn on versioning, and expect to open the sync app to sync. If that is too fiddly, keep Syncthing on the desktop and put the phone on Git.
